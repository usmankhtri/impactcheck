# ImpactCheck

**Understand what your code changes could affect before you merge.**

**Production Application**: [https://impactchange.vercel.app/](https://impactchange.vercel.app/)

---

## What it does

ImpactCheck is a developer review tool that analyzes code diffs and project changesets to identify potential impact areas across APIs, authentication guards, dependencies, database schemas, configuration, and automated tests.

Modern code changes often span multiple architectural boundaries in a single commit or pull request. ImpactCheck parses touched files and runs deterministic static heuristics to highlight concrete review focus areas, helping engineers and reviewers catch unintentional contract breaks, missing middleware, destructive SQL statements, or newly introduced required environment variables before merging.

## Features

- **Project ZIP Analysis**: Upload an uncompressed project archive (`.zip`) for in-browser extraction and analysis with Zip-Slip protection.
- **Folder Analysis**: Select a local project folder directly through standard browser directory APIs.
- **Before / After Folder Comparison**: Compare two local directories to calculate line-level unified diffs via Myers / LCS diffing.
- **Git Diff & Patch Support**: Upload `.diff` or `.patch` files, or paste raw diff text generated by Git.
- **Change Map**: Visual architectural relationship graph mapping cross-layer connections between API routes, services, database migrations, and UI components.
- **Breaking Change Watchlist**: Surfaces high-risk changes such as altered route contracts, removed authorization middleware, dropped schema columns, or removed exports.
- **Test Impact Assessment**: Identifies modified core application files that lack corresponding test modifications in the changeset.
- **Dependency Impact**: Scans package manifests (`package.json`, `requirements.txt`) for major semver bumps, added dependencies, and optional public OSV vulnerability advisory lookups (strictly parsing dependency blocks and ignoring scripts).
- **Change Noise Filtering**: Separates routine lockfile and generated bundle churn from substantive human-authored source logic.
- **Review Verification Checklist**: Generates an interactive, categorized checklist with progress tracking for PR review discussions.
- **Multi-Format Report Exports**: Export self-contained reports in Markdown (`.md`), HTML (`.html`), JSON (`.json`), or plain text (`.txt`).
- **Local History**: Preserves recent analyses in browser `localStorage` without cloud persistence or account requirements.
- **Complete Light & Dark Themes**: High-contrast, WCAG-compliant design system with automatic OS system preference detection.

## How it works

ImpactCheck uses deterministic static heuristics rather than generative language models:

1. **Input Normalization**: Ingests files or unified diff text and extracts structured files, hunks, additions, deletions, and metadata.
2. **Lexical & Structural Pattern Matching**: Analyzes AST-like token patterns (e.g. Express/Next route declarations, SQL DDL statements, package version semver deltas, environment variable accessors).
3. **Correlation & Deduplication**: Merges multi-line signals into unified findings with explicit Before/After evidence, severity rankings, confidence ratings, and suggested review actions.
4. **Interactive Visualization**: Renders findings across a synchronized three-panel workstation with keyboard navigation.

## Supported inputs

- **ZIP Archive (`.zip`)**: Client-side extracted archives with Zip-Slip path sanitization and 50MB safety caps.
- **Local Directory**: Uses the standard browser `webkitdirectory` API.
- **Two-Folder Comparison**: Compares base and head directories and generates line diffs.
- **Diff or Patch Files**: Upload `.diff`, `.patch`, or text files.
- **Pasted Git Diff**: Paste raw diffs created with `git diff main...HEAD` or `git show <commit>`.

## Privacy & Security

- **Client-Side Execution**: All parsing, diff generation, and heuristic evaluation runs locally in your browser memory.
- **Zero Source Code Execution**: ImpactCheck never executes uploaded code, scripts, binaries, or npm lifecycle hooks.
- **Untrusted Input Posture**: Archive paths and file contents are treated as untrusted strings. HTML report exports are strictly escaped to prevent script injection.
- **Optional Vulnerability Lookups**: When OSV lookups are enabled, only package names and version strings (e.g., `lodash@4.17.21`) are sent to the public OSV API (`api.osv.dev`). Source code is never sent.
- **Local Storage Control**: History and preferences are stored exclusively on your device in `localStorage`. History saving can be toggled off or cleared at any time in Settings.

## Deployment

ImpactCheck is designed for zero-configuration deployment to static hosting providers such as Vercel:

```bash
# Deploy with Vercel CLI
vercel --prod
```

The repository includes a `vercel.json` file configuring client-side SPA routing and standard security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`).

### Environment Variables

`VITE_APP_URL` is completely optional. When omitted, ImpactCheck uses `https://impactchange.vercel.app` or the browser's current origin.

```bash
# Optional production override
VITE_APP_URL="https://impactchange.vercel.app"
```

## Limitations

- **Static Heuristics**: Heuristic evaluation identifies patterns that warrant human attention. It cannot evaluate complex runtime dynamic router delegations or execution-path states.
- **Test Heuristic Scope**: Test impact evaluation is based strictly on files present in the analyzed changeset; existing tests elsewhere in the repository are not evaluated.
- **OSV Lookups**: The OSV database catalogs public advisories; the absence of an advisory does not guarantee absolute security.
